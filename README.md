# Hayate Agent: local persistent deployment example

This example runs an **already built public Hayate checkout**, not a published npm
package or a promised container image. It does not install Kubernetes resources,
Matrix operators, credentials or private infrastructure. It binds no listening
service by default. Review your own model/provider configuration before running.

## Public source dependency

Use https://github.com/hayate-agent/core/pull/2 at commit
`601e48f42f4060b487aa7fffc2727a7404582ce7` for the Hayate executable,
`HAYATE_AGENT_HOME` and `hayate-agent.yaml` naming. That PR was merged into public
main on 2026-11-02. This example still pins the exact tested commit above; it does
not require a released package or image. The selected
Core snapshot contains its audited plugin sources and immutable file lock;
follow that checkout's build/materialization instructions. A separately built
plugin checkout is not injected by this example. The independent public plugins
repository is https://github.com/hayate-agent/plugins; do not assume its older
main matches the lock of a different Core commit. No private repository access
should be necessary; stop if the selected Core build requires it.

After the selected public checkout's own tests/build have passed:

```sh
export HAYATE_INSTALL=/absolute/path/to/built/public/core
export HAYATE_AGENT_HOME="$HOME/.hayate-agent-example"
node "$HAYATE_INSTALL/dist/cli.js" init
# Edit $HAYATE_AGENT_HOME/hayate-agent.yaml for YOUR model/provider.
# Keep credentials out of Git; use the provider's documented credential storage.
node "$HAYATE_INSTALL/dist/cli.js" doctor
./run.sh
```

`run.sh` persists configuration and sessions in the specified home and executes
`hayate-agent run` through the selected built CLI. It refuses a missing config or
build. The config is generated by the selected executable, not copied from any
private agent. This avoids freezing an unrelated config schema in an example.
Stop with Ctrl-C; rerunning the same command reuses that home. This is a manual
foreground example, not an auto-restart service. Do not run it against an existing
agent home. Provider availability and authentication are the operator's concern.

## Publication boundary

These generic files originate in the publishing owner's `public/deployments/`
directory, with exact mapping and hashes in `ci/deployments_snapshot_policy.json`.
They are NOT a mirror of the internal deployment-base repository. That repository
contains private-infrastructure-specific templates and remains unchanged.
`PUBLIC-SNAPSHOT.json` records the precise source commit, file inventory and digest
when the reviewed offline exporter is used. Only allowlisted bytes plus generated
provenance enter a fresh Git root; no private source history is transported.

and Plugins repositories retain their own licenses. The files in this example
